## Build

From the repository root, run:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File source/tools/build-dashboard.ps1
```

The execution-policy override affects only this process.
It uses the existing local qnx650-sdk Docker image and license, with no network.
Evo input and license mounts are read-only. Output is ignored by Git under
`source/native/out/dashboard/`. The build never installs files.

The separate dashboard script enables the current gauge features consistently
and retains EngineCodes reading and clearing, including the confirmation screen.
Both use ordinary DME diagnostic services and require no MHD or Bootmod3 tune.
The original release build remains unchanged.
The stock-DME build replaces the MHD-specific ethanol channel with OBD oil
temperature. Stock frames use NBG5; the reference ethanol build retains NBG4.
Staging generates the card background with an OIL TEMP title and preserves
the clear-codes menu. It combines
the new binaries with source XML/manifests and packaged image archives.
Candidate folders and SHA256SUMS are under out/dashboard/.

## Batch deployment and diagnostic gateway

The current installer uses two SSH sessions regardless of selected app count:
one inventory read and one helper-plus-bundle upload. The static helper verifies
SHA256 for every extracted file and again after moving into Plugins. Final
verification runs inside the rollback transaction before success is recorded.
Uninstallation also uses two sessions and preserves modified-file checks.
No tar, shell printf, rmdir or openssl executable is required.

Local tests cover full bootstrap/install/restore, corrupt input, failed final
verification, hidden-file modification, SHA256 boundary vectors, path traversal,
symlink escape and gateway configuration. QNX candidates cross-compile.

The original gateway 169.254.21.3 was a reference-car constant. The owner suggested
169.254.20.21 for this F30, now confirmed by a live read-only probe from Evo:
RPM response 410C0A7C (671 RPM), speed 410D00 (0 km/h), coolant 410576 (78 C).
169.254.21.3 timed out. Internal .99 and .253 accepted TCP but did not return
the expected OBD reply. The confirmed address is the new installer's default.
All three apps now read
gateway-ip.txt beside the worker. Missing files retain the upstream reference
fallback; invalid files stop the worker request. There is no automatic scan or
write attempt in the applications.

Test-Evo-Diagnostics.cmd uploads a temporary bounded read-only probe in one SSH
session. It reads OBD RPM, speed and coolant through explicit known candidates
and saves raw results under .local/diagnostics. It does not clear codes or load
plugins. Internal network observations included VLAN73 addresses 160.48.199.97
and .99; observing an address or open TCP port is not proof of a DME response.
The complete native helper upload, bundle extraction, SHA verification and
five-address probe succeeded on QNX in 29.7 seconds, using one SSH connection.
The new app install/restore flow remains covered by host fixtures rather than
a live installation by the agent.
